# ChargeSafe 全过程开发记录体系

## 1. 目标

当前项目处于中期开发。文档体系用于持续记录事实、决策、验证与外部资产，不提前撰写最终交付结论。

## 2. 文档分层与唯一事实源

| 类型 | 建议位置 | 唯一事实范围 | 更新时机 |
| --- | --- | --- | --- |
| 动态项目入口 | `README.md` | 环境、真实命令、当前阶段、索引 | 启动方式/阶段变化 |
| 中期事实基线 | `docs/audit/midterm-development-baseline-audit.md` | 某提交点的完成状态 | 阶段结束重新出一版 |
| 证据索引 | `docs/audit/source-of-truth-evidence-index.md` | 代码路径映射 | 接口/页面/迁移变化 |
| 设计规范 | `docs/audit/new-frontend-design-guidelines.md` | UI tokens 与交互约束 | 设计决策变化 |
| 专项研究 | `docs/research/` | 候选与证据，不代表采用 | 调研或许可证变化 |
| 实施计划 | `docs/tasks/` | 未完成工作与验收 | 任务评审/完成 |
| ADR | `docs/process/adr/` | 为什么选/不选某方案 | 架构决策当日 |
| 开发日志 | `docs/process/logs/` | 实际实施与问题 | 每个开发批次 |
| 验证记录 | `docs/process/verification/` | 命令、环境、结果 | 每阶段验收 |
| 资产台账 | `docs/process/external-assets.md` | 外部资产许可唯一来源 | 下载前与提交前 |

数据库结构唯一事实始终是 Flyway 迁移；接口唯一事实是 Controller/DTO；命令唯一事实是 `pom.xml`、`package.json` 和脚本。文档不得复制维护第二份易漂移的完整定义。

## 8. UI/UX 整改记录

每个页面记录：用户任务、原问题、截图基线、设计依据、状态语义、键盘/移动端/错误状态、改后截图与回归。避免只记录“换颜色、加阴影”。管理端、大屏、小程序分别维护，不复制一套通用结论。

## 9. 数据库演进记录

- V1-V5 只记录事实和 checksum 基线，不修改文件。
- 每个新迁移说明业务理由、前置数据、兼容性、回滚策略和验证 SQL。
- 不手工写 `flyway_schema_history`，不 repair/clean 掩盖问题。
- 场景坐标只有在前端配置验证后才进入新迁移提案。

## 10. 测试记录

按后端、管理端、小程序、大屏分开记录。失败必须保留第一条根因和环境；不得用 `--force`、跳过测试或静态截图替代真实验证。当前后端 JDK 21/Mockito agent 失败应作为环境基线问题跟踪。

## 11. 最终交付前汇总

最终阶段从这些动态事实源生成“一份总说明 + 专题文档”：需求范围、架构、数据库/Flyway、后端、管理端、小程序、大屏、API/权限、测试、环境交接、用户操作、已知问题。历史调研与过时计划保留归档标识，不混入当前操作指南。

最终报告只有在：工作区对应提交明确、P0/P1 关闭、三端构建与主路径验证通过、迁移可复现、资产许可完整、所有“已实现”可追溯时才能开始定稿。
