# 张健-调研记录

## 负责方向

可视化大屏 + 3D 场景方向。

本次调研不是直接写代码，也不是照搬别人的项目，而是为 ChargeSafe 后续页面优化、数据大屏、设备监控和 3D 场景提供参考。重点关注这些问题：

1. 大屏页面怎么布局；
2. 图表怎么展示端口、订单、工单、隐患和告警；
3. 充电设备状态怎么用颜色、标签、闪烁、弹窗表现；
4. 3D 场景能不能改造成社区、车棚、充电桩、电动车；
5. 哪些效果适合我们项目第一阶段落地，哪些适合后续扩展。

## 当前项目中可直接对接的内容

根据项目文档和现有代码，ChargeSafe 已经具备做可视化大屏的基础数据：

| ChargeSafe 数据或模块 | 可视化方式 | 可参考效果 |
|---|---|---|
| 端口总数、空闲端口、充电中、故障端口 | 顶部数字卡片、环形图、端口状态矩阵 | 数字翻牌、状态色块 |
| 今日预约、今日订单 | 趋势折线图、柱状图、滚动列表 | 订单趋势、实时预约动态 |
| 维修工单、待处理工单 | 告警列表、状态漏斗、工单滚动表 | 工单派发动态 |
| 安全隐患、待整改隐患 | 风险等级图、隐患列表、闪烁提示 | 隐患预警 |
| `alarm_record` 告警记录 | 告警中心、故障排行、红色闪烁点位 | 设备告警大屏 |
| 社区、车棚、设备、端口层级 | 2D 平面图或 3D 场景 | 社区-车棚-充电桩-端口 |
| 端口状态 `IDLE / RESERVED / CHARGING / FAULT / MAINTENANCE / DISABLED / OFFLINE` | 不同颜色和图标 | 设备点位状态 |

我筛选资料时优先选这几类：

1. 和 ChargeSafe 技术栈接近：Vue3、Vite、ECharts、Element Plus、Three.js；
2. 能看出页面布局或源码结构；
3. 能改造成社区充电场景；
4. 有截图、演示或 README，便于组长快速判断；
5. 不只看炫酷程度，更看是否能对应我们的模块和数据。

## 技术路线对比

| 方案 | 适合做什么 | 优点 | 风险或不足 | 对 ChargeSafe 的建议 |
|---|---|---|---|---|
| Vue3 + ECharts | 统计大屏、图表、趋势、状态分布 | 当前项目已经使用，落地最快 | 视觉上偏 2D，缺少沉浸式场景 | 第一阶段优先做 |
| Vue3 + ECharts + DataV 类组件 | 科技风边框、数字翻牌、滚动表 | 大屏效果明显 | 组件质量要筛选，可能有兼容问题 | 可借鉴样式和组件 |
| Vue3 + Three.js | 3D 车棚、充电桩、设备点位 | 自由度高，适合项目展示 | 模型、性能、交互复杂度较高 | 第二阶段做简化 3D |
| ThingJS / HT for Web | 数字孪生、园区级 3D 平台 | 效果成熟，业务表达强 | 商业平台，未必适合直接接入 | 主要参考效果和方案 |
| 静态 HTML 大屏模板 | 视觉参考、页面布局参考 | 找样式快 | 技术栈不一致，代码不一定好维护 | 只参考布局和配色 |

## 我建议 ChargeSafe 大屏第一版这样设计

页面名称定为：`社区充电安全态势大屏`。

视觉设计建议从原来的 **Cyberpunk 暗夜霓虹** 修正为 **克制的社区充电安全运维风**。原因是 ChargeSafe 的重点是端口状态、故障告警、维修工单、巡检隐患和统计分析，过多霓虹背景会抢走业务数据的注意力，也容易显得像通用模板。

### 页面布局结构

```text
┌────────────────────────────────────────────────────────────┐
│ ChargeSafe 社区充电安全态势大屏      时间 / 社区 / 运维角色 │
├───────────────┬────────────────────────────┬───────────────┤
│ 左侧图表       │ 中间主视觉                  │ 右侧列表       │
│ ┌───────────┐ │ ┌────────────────────────┐ │ ┌───────────┐ │
```

## 补充：可视化与 3D 落地深度设计方案

### 3.1 大屏自适应适配方案
大屏开发的核心挑战之一是多分辨率适配（如 1920x1080 与 4K 屏幕）。建议采用 **CSS `transform: scale()` 缩放方案**，在保持 16:9 设计比例的同时自动缩放居中，避免图表拉伸变形：

```javascript
// Scale.js / Hook
import { ref, onMounted, onUnmounted } from 'vue'

export function useScreenScale(designWidth = 1920, designHeight = 1080) {
  const scale = ref(1)
  
  const updateScale = () => {
    const currentRatio = window.innerWidth / window.innerHeight
    const designRatio = designWidth / designHeight
    
    if (currentRatio < designRatio) {
      // 宽度不够，按宽度缩放
      scale.value = window.innerWidth / designWidth
    } else {
      // 高度不够，按高度缩放
      scale.value = window.innerHeight / designHeight
    }
  }

  onMounted(() => {
    updateScale()
    window.addEventListener('resize', updateScale)
  })

  onUnmounted(() => {
    window.removeEventListener('resize', updateScale)
  })

  return { scale }
}
```
在大屏页面根容器绑定：
`style="transform: scale(scale) translate(-50%, -50%); transform-origin: left top; position: absolute; left: 50%; top: 50%; width: 1920px; height: 1080px;"`

### 3.2 大屏与 3D 页面组件架构设计
为配合 Vue3 + Vite 的模块化开发，建议在 `charge-safe-admin` 项目中建立独立的组件目录结构，解耦图表配置与核心逻辑：

### 3.3 3D 场景开发路线与技术细化
在第二阶段落地 3D 可视化时，为降低原生 Three.js 繁琐的样板代码，推荐使用 **TresJS** (Vue3 特化型 3D 框架)，它允许以 Vue 组件的声明式语法开发 3D：

1. **库引入**：`npm install three @tresjs/core @tresjs/caniuse`
2. **场景搭建**：
```html
<template>
  <TresCanvas clear-color="#050812" shadows>
    <TresPerspectiveCamera :position="[15, 10, 15]" :look-at="[0, 0, 0]" />
    <OrbitControls />
    <ambientLight :intensity="0.5" />
    <directionalLight :position="[10, 8, 5]" :intensity="1" cast-shadow />
    
    <!-- 充电桩/车棚模型加载 -->
    <Suspense>
      <GLTFModel path="/models/charging_station.glb" />
    </Suspense>
    
    <!-- 动态端口状态指示灯 (根据后端数据实时改变 Mesh 颜色) -->
    <mesh v-for="port in ports" :key="port.id" :position="port.position">
      <sphereGeometry :args="[0.2, 32, 32]" />
      <meshStandardMaterial :color="getPortStatusColor(port.status)" :emissive="getPortStatusColor(port.status)" :emissiveIntensity="1.5" />
    </mesh>
  </TresCanvas>
</template>
```
3. **性能优化**：
   - 静态几何体（车棚结构、地面）合并成单个 Mesh 减少 Draw Call。
   - 禁用不必要的阴影计算。
   - 对 3D 模型进行 Draco 压缩（`.glb`），保证页面秒开。

### 3.4 接口对接与 ECharts 数据流绑定
根据当前项目说明和现有接口，第一版大屏只采用轮询（Polling）从后端拉取统计数据，不写成 WebSocket 实时推送：
- **实时告警滚动**：每 30 到 60 秒请求告警、工单或隐患接口，追加到前端滚动队列。
- **图表自动重绘**：在 ECharts 组件中通过 `watch` 监听 Pinia/父组件传入的 API 数据源，触发 `chart.setOption()` 实现平滑过渡动画：
```javascript
watch(() => props.chartData, (newData) => {
  if (chartInstance) {
    chartInstance.setOption({
      series: [{ data: formatData(newData) }]
    })
  }
}, { deep: true })
```

# 张健-素材筛选补充

> 本文档用于补充 `张健-调研记录.md`：在不改变项目技术边界的前提下，为 ChargeSafe 可视化大屏重新筛选更符合主题、不过度花哨、许可更清楚的素材来源。

## 1. 筛选基准

本次筛选按远程仓库上一次提交 `dd69ad1 docs: 更新技术文档，添加版本日志 v0.2.0` 的项目说明执行。

项目约束：

| 约束 | 对素材选择的影响 |
|---|---|
| Web 管理端技术栈是 Vue3、Vite、Element Plus、Pinia、Axios、ECharts | 第一版素材只做页面辅助，不新增重型视觉框架 |
| 项目不接入真实充电硬件 | 文案和画面不能暗示已有真实 IoT 接入 |
| 项目不做复杂物联网长连接 | 第一版不要把素材包装成 WebSocket 实时监控能力 |
| 项目不做真实电量采集 | 素材可以表现充电设备，但数据表现仍以模拟统计为准 |
| 第一版后端已有统计、端口、工单、隐患等接口 | 视觉重点放在端口状态、告警、工单、隐患，不做纯装饰 |
| 调研图和运行图要分开 | 候选素材先放 `docs/research/images/` 或只记录链接，真正使用时再复制到 `charge-safe-admin/src/assets/images/big-screen/` |

最终风格方向：

- 不采用高饱和紫粉霓虹和赛博朋克城市背景；
- 不采用大片科技边框、HUD 贴图、光污染背景；
- 采用“社区充电安全运维中心”的克制深色风格；
- 真实设备素材只作为小面积辅助，核心还是图表、状态矩阵、告警列表和业务数据。

## 2. 素材分类建议

| 类型 | 推荐程度 | 用途 | 注意点 |
|---|---|---|---|
| 真实充电接口 / 充电设备 close-up | 高 | 右侧媒体面板、顶部背景局部、空状态图 | 裁掉品牌 logo、车牌、人脸 |

## 5. 最推荐的组合

如果只选一套最稳的素材方案，建议这样做：

1. 中间主视觉：用自制 CSS / Vue 端口状态矩阵，不依赖外部图。

4. 电动自行车主题补充：从 Wikimedia Commons 里找 `CC0` 或许可清楚的 E-bike charging station 图，只作为调研或局部参考。

- 主题更像“充电安全运维”，不是泛科技模板；
- 页面不会被动图和背景抢走注意力；
- 素材数量少，维护简单；
- 版权和来源可追踪；
- 运行目录不会变成素材仓库。

## 6. 素材处理规范

静态图：

- 优先格式：`webp`；
- 备用格式：`jpg`；
- 建议尺寸：宽度 900px 到 1400px；
- 单文件体积：尽量小于 1MB；
- 处理方式：裁剪主体、压暗、去掉不必要边缘、避免明显 logo；
- 命名示例：`charging-connector-closeup.webp`、`community-charging-shelter.webp`。

动图 / 视频：

- 优先格式：`mp4` 或 `webm`；
- GIF 只作为调研记录或临时预览，不建议作为最终运行素材；
- 建议时长：3 到 8 秒循环；
- 单文件体积：尽量小于 3MB；
- 处理方式：降低亮度、降低码率、裁掉品牌、人脸、车牌；
- 命名示例：`charging-connector-loop.mp4`、`charging-status-panel.webm`。

运行目录：

```text
charge-safe-admin/src/assets/images/big-screen/
```

只允许放最终使用素材，例如：

```text
charging-connector-closeup.webp
charging-connector-loop.mp4
```

不要放：

```text
zhangjian-xxx-screenshot.png
参考图.png
未使用素材.gif
网页截图.jpg
```

# ChargeSafe 可视化大屏开发指南

> 面向张健负责的“可视化大屏 + 3D 场景方向”。本文档以远程仓库上一次提交 `dd69ad1 docs: 更新技术文档，添加版本日志 v0.2.0` 的项目说明为基准，用于把调研成果转成后续开发和素材使用方案。

## 1. 当前结论

大屏第一版建议先做 **Vue3 + ECharts 的 2D 运维态势大屏**，不要一开始直接上复杂 3D。

原因：

- 当前 `charge-safe-admin` 已经有 Vue3、Vite、Element Plus、Pinia、Axios、ECharts。
- 后端已有 `/api/statistics/dashboard` 和 `/api/ports/statistics`，可以直接支撑第一版指标。
- 项目边界明确写了“不接入真实充电硬件”“不做复杂物联网长连接”“不做真实电量采集”，所以第一版不要写成真实 IoT 大屏。
- Three.js / TresJS 需要额外依赖、模型资源和性能调优，适合作为第二阶段增强。
- 目前没有 WebSocket 接口，第一版用定时轮询更符合现有接口条件。

第一版目标页面：`社区充电安全态势大屏`。

视觉方向从原来的“暗夜霓虹 / Cyberpunk”调整为 **克制的社区充电安全运维风**：深色底、清晰图表、真实充电设备素材点缀、状态色服务业务，不堆霓虹边框和高饱和装饰。

- 大量未接接口的假按钮；
- 大面积无业务含义的科技纹理、霓虹边框和光效。

## 5. 视觉规范

核心色建议：

| 用途 | 颜色 | 说明 |
|---|---|---|
| 页面背景 | `#07111f` | 深蓝黑，降低眩光 |
| 面板背景 | `rgba(8, 18, 32, 0.86)` | 稳定承载图表 |

图表原则：

- 环形图、折线图、柱状图颜色按业务状态映射，不用随机渐变；
- 故障红色可以强调，但不要整块页面闪烁；
- 图例、单位、数值必须清楚；
- 图表背景保持透明或深色，不叠复杂贴图；
- 中间主视觉优先用“端口状态矩阵 / 车棚示意图”，不是单纯放一张炫酷图。

## 6. 素材选型原则

本项目更适合这些素材：

- 真实或半真实的充电设备、充电接口、充电车棚、停车充电区域；
- 与社区、园区、物业运维、设备安全有关的画面；
- 光线干净、背景简单、设备主体清楚的图片；
- 可以裁成横向小图、面板插图或右侧媒体卡片的素材；
- 版权许可清楚，能记录来源链接的素材。

不建议使用这些素材：

- 紫粉霓虹、赛博城市、纯 HUD 边框、无业务含义的科技纹理；
- 只拍汽车外观但看不到充电设备的图；
- 明显带车企、充电运营商品牌 logo 的图；
- 有清晰人脸、车牌、商业商标且许可不明确的图；
- 从博客、商业案例、产品官网直接截取并放入项目运行目录；
- 没有来源、没有许可说明、无法追溯的图片。

推荐素材来源见前文“素材筛选补充”部分。

## 7. 大屏适配方案

基准分辨率建议使用 `1920 * 1080`。第一版可以自己封装 `ScaleBox`，不必立刻安装第三方缩放库。

关键逻辑：

```js
import { ref, onMounted, onUnmounted } from 'vue'

export function useScreenScale(designWidth = 1920, designHeight = 1080) {
  const scale = ref(1)

  const updateScale = () => {
    const scaleX = window.innerWidth / designWidth
    const scaleY = window.innerHeight / designHeight
    scale.value = Math.min(scaleX, scaleY)
  }

  onMounted(() => {
    updateScale()
    window.addEventListener('resize', updateScale)
  })

  onUnmounted(() => {
    window.removeEventListener('resize', updateScale)
  })

  return { scale }
}
```

页面根容器建议：

```css
.screen-stage {
  width: 1920px;
  height: 1080px;
  transform-origin: left top;
}
```

不要让每个图表自己按浏览器窗口随意伸缩，否则容易出现文字重叠、图表比例失真。

## 10. 3D 第二阶段建议

第二阶段再评估 Three.js / TresJS：

- 先用简单几何体做“车棚 + 充电桩 + 端口灯”，不要一开始找复杂模型；
- 端口灯颜色直接映射后端状态；
- `FAULT` 状态可以做红色闪烁，但控制频率；
- 点击端口弹出详情卡片；
- 后续再替换 GLB / GLTF 模型；
- 不要引入商业 3D 平台素材到运行目录，除非许可明确。

需要新增依赖时再安装：

```bash
npm install three
```

TresJS 可以作为后续选择，但不是第一版必需项。

## 11. 风险点

| 风险 | 说明 | 处理建议 |
|---|---|---|
| 素材乱放 | 调研图和前端运行图混在一起 | 调研图只放 `docs/research/images`，运行图只放实际引用文件 |
| 素材版权不清 | 官网、博客、商业案例截图不能直接当运行素材 | 优先使用 Pexels、Unsplash、Pixabay、Wikimedia Commons，并记录链接和许可 |
| 素材过度装饰 | 霓虹、赛博、HUD 边框会盖过业务数据 | 素材只做辅助，状态和图表优先 |
| 过早做 3D | 会拖慢进度，且缺模型资源 | 第一版先做 2D 大屏 |
| 接口不存在 | 趋势图、WebSocket 暂无接口 | 先 mock，后端补接口后替换 |
| 大屏适配失控 | 图表和文字在不同分辨率变形 | 使用统一 `1920 * 1080` 缩放容器 |
| 账号权限误判 | 普通账号可能看不到部分菜单 | 大屏路由按展示需求配置权限，普通后台菜单按 RBAC 保持原逻辑 |
