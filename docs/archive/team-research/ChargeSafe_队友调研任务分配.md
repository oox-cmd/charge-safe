# ChargeSafe 队友调研任务分配说明

> 项目名称：ChargeSafe 社区充电安全运维平台  
> 调研目标：去 GitHub、CSDN、博客园、掘金、B站等平台找可以借鉴的成熟项目或功能点，为后续开发、页面优化、可视化大屏和 3D 效果提供参考。

---

## 0. 先说清楚：这次不是让大家直接写代码

大家先不要着急写功能，也不要随便复制别人的项目。  
这次任务主要是：**找资料、看别人怎么做、总结哪些地方可以借鉴**。

我们不是要找到一个和 ChargeSafe 完全一样的项目，而是可以分别借鉴：

- 某个项目的后台页面布局；
- 某个项目的数据库表设计；
- 某个项目的登录权限设计；
- 某个项目的工单流程；
- 某个项目的 ECharts 数据看板；
- 某个项目的 3D 场景效果；
- 某个小程序的预约、扫码、报修页面。

一句话：**不用找一个全能项目，只要找到某个点做得好，就有价值。**

---

## 1. 大家先做的共同准备

每个人先做这几步：

1. 拉取 GitHub 仓库。
2. 看一下 README 和项目目录结构。
3. 不需要完全看懂所有代码，先知道项目大概分成：后端、Web 管理端、小程序端、数据库、文档。
4. 在项目里创建自己的调研文档。

文档放在：

```text
docs/research/
```

命名格式：

```text
docs/research/姓名-调研记录.md
```

例如：

```text
docs/research/张三-调研记录.md
```

## 2. 每条资料统一记录格式

每找到一个项目或文章，都按下面这个格式写，不要只贴链接。

```markdown
## 资料 1：项目或文章名称

- 链接：
- 来源：GitHub / CSDN / 博客园 / 掘金 / B站 / 其他
- 技术栈：例如 Spring Boot、Vue3、Element Plus、ECharts、uni-app、Three.js
- 这个资料主要讲什么：
- 我们可以借鉴什么：
- 对应 ChargeSafe 哪个模块：
- 我觉得是否值得参考：值得 / 一般 / 不太值得
- 备注或截图说明：
```

示例：

```markdown
## 资料 1：某某物业报修管理系统

- 链接：https://xxxx
- 来源：GitHub
- 技术栈：Spring Boot + Vue + MyBatis-Plus
- 这个资料主要讲什么：居民提交报修，管理员派单，维修人员处理工单。
- 我们可以借鉴什么：报修记录和维修工单分开设计，工单有“待派单、处理中、待验收、已完成”等状态。
- 对应 ChargeSafe 哪个模块：报修工单模块。
- 我觉得是否值得参考：值得。
- 备注或截图说明：它的工单状态流程比较清楚，但页面比较普通。
```

# 4. 不要踩的坑

大家调研时注意：

1. 不要只交一堆链接，必须写清楚“这个资料对我们有什么用”。
2. 不要找太老的技术，优先看 Spring Boot、Vue、Vue3、Element Plus、ECharts、uni-app、Three.js。
3. 不要求完全看懂源码，但要能说出哪里值得参考。
4. 不要直接复制别人整个项目。
5. 可以借鉴页面布局、数据库字段、接口命名、状态流程、交互逻辑。
6. 如果项目跑不起来也没关系，只要页面、代码、数据库设计有参考价值，也可以记录。
7. 大屏和 3D 项目不一定要完全符合充电站，只要效果能改造成 ChargeSafe 就可以。
8. 看到“毕业设计源码合集”时要谨慎，优先找有 README、有截图、有目录结构、有代码说明的项目。
