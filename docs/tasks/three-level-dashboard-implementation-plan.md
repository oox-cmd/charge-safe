# ChargeSafe 三级三维大屏实施计划

> 本文是待确认计划，不代表功能已实现。任何依赖、模型、接口或迁移变更都需单独评审。

## 1. 共同前置条件

1. 统一“车棚/充电站”的业务术语与 ID。
2. 修复统计接口认证边界；大屏默认位于管理端并使用现有登录、菜单和权限体系。教师免登录演示模式另行设计，不得绕过认证。
3. 形成 9 种端口状态唯一字典。
4. 明确现有聚合指标口径，禁止把模拟数混入真实数据。
5. 为每个外部资产保存来源、作者、许可证、下载日期和修改记录。

## 2. 方案 1：最小可行版本（MVP）

### 2.1 范围

- 原生 Three.js 统一渲染；一级固定使用 `three-globe`，Vue 负责页面、状态和生命周期，Three 引擎封装到独立组件、模块与 composable。
- 只展示项目相关社区标点，不画全球假数据。
- 二级使用程序化道路、建筑、地面和少量 Kenney CC0 模块，采用非测绘级近似布局，不接真实地图底图。
- 三级使用程序化车棚、柜体和 InstancedMesh 端口。
- 场景坐标存在前端配置；后端提供真实 ID 和状态。
- 不新增数据库字段或迁移，不做真实历史回放、WebSocket、后台场景编辑器或多社区场景管理。

### 2.2 验收

- 地球 → 社区 → 站点及返回路径稳定。
- 地球聚焦小区的镜头转场可中断，加载、错误和 WebGL 降级提示可见。
- 小区中站点标识可点击，单站按空间布局展示端口和详情。
- 端口对象都能按真实 `portId` 点击并展示状态。
- 9 状态可区分，颜色之外有图标/文字/形状。
- API 失败、WebGL 不支持和模型失败均有降级。
- 场景切换后 GPU 资源可释放，连续切换 20 次无持续增长。

## 3. 方案 2：推荐演示版本

在 MVP 上增加：

- `camera-controls` 或等价镜头预设与可中断飞入；
- 筛选后的 Poly Haven 低分辨率配电箱/摄像头/消防器材；
- 站点告警锚点、端口详情、容量与趋势小面板；
- GLB 分层懒加载、Draco/Meshopt 与 KTX2 评估；
- 选择 Outline、低频状态过渡和 `prefers-reduced-motion`；
- 一个 1920×1080 主演示视图和 1366×768 可用视图。

验收重点不是模型写实，而是演示者能在 2 分钟内解释“区域风险 → 哪个社区 → 哪个站点 → 哪个端口”。

## 4. 方案 3：后期增强版本

只在数据与演示版稳定后评估：MapLibre 真实地图、可配置场景、Blender 微调、状态时间轴、风险评分、负载趋势、WebSocket/SSE。当前不采用 MapLibre 或 Cesium；真实 GIS、地形、3D Tiles 或 WGS84 需求成立后再重新评审。

## 6. 文件修改范围预览

预计新增独立 `views/bigscreen3d/`，复用 `src/api/statistics.js` 或新增专用 API 文件；后端预计只新增 Controller/VO/查询，不修改现有迁移。是否替换 `/bigscreen` 路由必须等 MVP 通过，避免破坏现有二维演示页。

## 7. 性能预算

| 项目 | 建议预算 | 原因 | 优化方式 |
| --- | --- | --- | --- |
| 一级首屏 JS 增量 | gzip ≤ 250 KB | 管理端已有大包 | 路由动态 import、只引 Three 子模块 |
| 一级资源 | ≤ 2 MB | 快速显示入口 | 程序化地球、压缩纹理 |
| 二级场景 | 首次 ≤ 6 MB | 社区为示意 | CC0 低多边形、实例化、懒加载 |
| 三级场景 | 首次 ≤ 10 MB | 允许少量近景细节 | 1K 贴图、Draco/Meshopt、KTX2 评估 |
| 单场三角面 | MVP ≤ 300K | 普通教学机稳定 | LOD、减面、不可见剔除 |
| Draw Call | 主视图 ≤ 150 | 保持流畅 | InstancedMesh、合并静态材质 |
| 常驻纹理 | ≤ 128 MB GPU 估算 | WSL/集显兼容 | 1K 优先、释放、复用 |
| FPS | 1080p 中档机 ≥ 45；交互不低于 30 | 演示稳定优先 | 动态分辨率、关闭重后处理 |
| API 刷新 | 默认 10-15 秒可配置轮询 | 当前不是真实 IoT | 页面隐藏暂停轮询与渲染、请求去重 |
| 场景切换 | 可操作反馈 < 100 ms；主要资源 3 秒内 | 避免“卡死”感 | skeleton、预加载下一层最小资源 |

预算需由目标演示机原型修正，不能视为已达成指标。

## 8. 风险与停止条件

- 端口级 API 不存在：停止做三级真实绑定，不用随机端口替代。
- 资产许可证不明：不下载、不提交、不“先用再补”。
- 模型节点不可稳定拆分：改用显式实例与配置，不用节点名硬绑。
- Three 原型无法可靠 dispose：先解决生命周期再扩场景；不引入 TresJS 绕开问题。
- 后端权限未修：不把真实运维数据暴露在公开路由。
- MVP 超预算：删装饰模型和后处理，不删状态文本和错误提示。

## 9. 已确认边界与后续用户确认

已确认 MVP：原生 Three.js + `three-globe`、登录后访问、示意性低多边形小区、程序化站点、前端场景坐标、真实业务 ID/状态、CC0 资产、10-15 秒轮询。当前不引入 Globe.GL、TresJS、MapLibre、Cesium、WebSocket，不新增迁移，也不购买或等待完整充电站模型。

MVP 必须完成地球页、聚焦小区转场、示意小区、站点标识、单站端口布局、真实状态映射、端口选择与详情、返回上级、加载/错误/WebGL 降级。MVP 不包含真实 GIS、测绘级小区、机器学习预测、时间轴、超精细或 Blender 定制模型、数字孪生编辑器和多社区场景管理后台。

仍需用户确认：推荐演示版最终视觉稿、具体 CC0 资产清单、是否采用少量写实设备点缀，以及每一个候选 CC BY 资产（若确有必要）。CC BY 必须逐项记录作者、来源 URL、License 与署名方式；代码和模型许可证不得混同。
